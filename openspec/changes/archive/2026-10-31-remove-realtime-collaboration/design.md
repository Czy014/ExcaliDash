# Design

## Context

动机和范围见 [proposal.md](proposal.md)。当前基线是 `0f9be2d`，版本为 `0.6.7`，源码中可见以下接入点：

- `frontend/src/pages/Editor.tsx` 装配 `useEditorCollaboration`、`useEditorBroadcast`、`useEditorSceneApi` 和 `useEditorPersistence`。协作引用也进入画布事件和编辑器界面，不能只删除一个 Hook 或封锁代理。
- `useEditorPersistence.ts` 使用 HTTP 保存，收到 409 后通过 `reconcileSave.ts` 读取、合并并重试。`useEditorCommands.ts` 另有手动保存、返回和 `pagehide` 的 keepalive 保存；组件卸载还会 flush 防抖队列。
- `backend/src/routes/dashboard/sceneUpdate.ts` 已用事务和带版本条件的更新保护场景、历史快照及图片引用。`drawingCreateUpdateRoutes.ts` 对过期的显式版本返回 409，不需要重新设计并发控制。
- `backend/src/index.ts` 装配 Socket.IO；dashboard 和 storage routes 会广播已提交场景或服务器变化，分享路由也有协作连接的权限重验。
- `frontend/src/utils/rehydrateFiles.ts` 的 `rehydrateFilesForExport` 能严格取得图片内容。已有 `POST /drawings` 接受完整场景，但前端 `createDrawing` 封装当前只创建空图；现有 duplicate 接口复制的是服务器场景。
- 现有测试包含 `frontend/tests/editor-save-safety.test.tsx`、协作和图片安全测试、后端图片/历史/分享集成测试及 `e2e/tests/` 下的工作流测试。

## Goals / Non-Goals

**Goals:**

- 将单页编辑和 HTTP 持久化保留下来，完整删除实时协作的实现及装配。
- 用现有服务端版本检查决定写入是否成功，用本地草稿保护未成功写入的内容。
- 使自动保存、手动保存和离开页面的行为遵守同一组保存状态。

**Non-Goals:**

- 不引入编辑锁、租约、分布式协调或另一种实时同步协议。
- 不改变数据库模型、HTTP 权限模型、现有认证方式及分享角色。
- 不在本 change 中处理原生 `/draw/` 前缀、生产数据升级或 Homebase 集成。

## Decisions

### 1. 从源码移除实时协作

前端删除协作连接、光标、成员展示和广播路径；保留本地画布操作、文件加载及保存安全检查。后端删除 Socket.IO 服务及各路由的广播、连接重验参数，HTTP 请求继续独立检查权限。同步移除双方直接依赖、lockfile 条目以及 Vite、`frontend/nginx.conf.template` 的协作代理。

清理只删除已无调用者的协作逻辑；文件重建、元素排序等仍用于本地编辑的工具继续使用。不保留空实现、兼容开关或让客户端不断重连的无效入口。相比仅隐藏 UI 或屏蔽代理，源码删除可以同时消除后台依赖和保存链路中的交叉引用。

### 2. 复用事务版本检查，统一编辑器保存状态

保留服务端现有的显式版本检查和事务，不改变其他 HTTP 调用者已有的输入契约。编辑器必须成功加载绘图版本后才能提交场景，每次成功保存再接收返回的新版本。

在现有编辑器保存 Hook 中集中管理未修改、未保存、保存中及冲突状态，不另建通用状态机框架。收到 409 后立即记录冲突，取消防抖请求；每个队列任务真正发送前再次检查状态和绘图会话。手动保存、返回、卸载、`pagehide` keepalive 和相关预览写入都使用同一冲突检查。已发出的请求仍由服务端版本条件保护。

删除 409 自动合并重试路径。请求成功只确认它捕获的本地修改序号：如果等待响应期间又发生编辑，不清除新草稿，也不把页面错误标记为已保存。切换绘图后的旧响应不能更新新绘图的版本和状态。网络失败继续保持未保存状态，不伪装成版本冲突。

### 3. 使用 IndexedDB 保存页面自己的草稿

复用浏览器 IndexedDB，不增加存储框架或服务器草稿表。每份草稿保存格式版本、服务/账户标识、绘图 ID、页面实例 ID、基础场景版本、修改序号、时间及完整本地场景。图片保留已有内容和未上传的本地字节，不能只存无法恢复的临时 Blob URL。

页面实例 ID 在每次页面初始化时独立生成，不能只复用可能被“复制标签页”复制的 sessionStorage 标识。重新打开时按当前账户和绘图列出可恢复草稿，恢复是用户操作，不自动写回原图；其他活跃页面的草稿不被恢复页覆盖或删除。

场景修改过程中持续保存草稿，不把持久化工作全部留到页面退出。服务器成功确认后只清理本页已确认的修改；较新的草稿保留。存储不可用或超限时显示本地保护失败，仍可进行正常 HTTP 保存和已有导出。承诺范围是已完成本地事务的草稿，不能保证浏览器清理站点数据或突然断电前尚未落盘的修改。

### 4. 冲突恢复使用已有读取和创建接口

“加载最新版本”先明确确认放弃当前改动；保持草稿到读取成功，再替换画布、版本和本页保存状态。读取失败保留原画布；只清理用户明确放弃的本页草稿。

“另存为副本”捕获本页场景，复用 `rehydrateFilesForExport` 严格取得图片，再通过现有 `POST /drawings` 一次创建完整新图。扩展前端创建封装以支持完整场景；不使用复制服务器旧场景的 duplicate 接口，也不先创建空图后逐步补内容。新图默认进入当前用户的未分类列表，使用派生副本名称；创建成功后取得新 ID 和版本再切换编辑会话。

新图图片必须由新图自己的存储引用支持，不能继续依赖原图被删除后会失效的地址。执行加载最新或另存副本时暂时冻结本页画布并禁用重复操作，避免等待期间的新笔画在切换时丢失；失败回到保留画布和草稿的冲突状态。缺少创建权限时遵守原权限错误，并保留已有导出方式，不扩大权限。

### 5. 在页面重新获得焦点时按需读取

移除协作后，用 `focus` 或恢复可见事件在页面没有未保存内容、保存请求、冲突或待恢复草稿时检查最新场景，不增加定时轮询。

发起读取时捕获绘图会话和本地修改序号，应用返回值前再检查；期间一旦开始编辑就丢弃该读取结果。断网不清空画布；重连后保存仍携带基础版本，由正常冲突路径处理其他设备已保存的修改。

## Risks / Trade-offs

- [排队或退出保存绕过冲突] → 在实际发送前统一检查，使用假时钟单测覆盖防抖、队列、手动保存、返回、卸载和 keepalive。
- [保存响应晚到而清理新改动] → 草稿与确认按本地修改序号处理，保留已有绘图会话隔离测试。
- [大图片或草稿配额不足] → 使用 IndexedDB 并显式显示存储错误；不承诺超过浏览器容量的本地保护，也不静默删其他草稿腾空间。
- [副本仍引用原图图片] → 先严格重建图片再创建，验证在测试数据库删除原图后副本仍完整可读。
- [不再实时刷新其他页面] → 未修改页面重新获得焦点时读取；有改动的页面通过冲突处理决定内容去向。
- [浏览器退出事件不可靠] → 在编辑过程中落盘，keepalive 只作为尽力保存，不把请求已发出视为保存已成功。
- [环境和线上版本不同] → 本机检查时 Node 为 24.21.0，低于项目最低 24.22.1；实施前使用符合要求的工具链。Homebase 当前配置为 0.6.6，未来生产接入须另外验证。

## Migration Plan

本 change 在独立功能分支开发并通过隔离测试，不部署 keeper，不执行真实备份或恢复。保留 `0.6.7` 的数据库模型和现有文件格式；本地草稿使用独立的格式版本，不迁入生产数据库。

代码完成后先验证现有绘图库场景和新保存流程，再同步、归档主规格并推送实现分支。生产镜像发布、`0.6.6` 数据兼容验证、Homebase 路由和回滚由后续独立集成 change 负责；当前不合入 `main` 或替换生产镜像。
